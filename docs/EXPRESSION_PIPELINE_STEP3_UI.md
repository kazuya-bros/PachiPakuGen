# Expression Asset Pipeline STEP3 UI Design

> [!NOTE]
> この文書はSTEP 3初期案の履歴資料です。SAM3ゲート案は現行v0.4.0 UIへ実装されていません。現行仕様はREADMEを参照してください。

## 1. Direction

通常ユーザー向けの主導線を `表情セット作成` の一本に統合する。
新規制作の必須入力は、開眼・口が確認できる立ち絵1枚だけとする。
See-Through は外部で実行させず、PachiPakuGen が管理する内蔵ワーカーとして実行する。

既存の `素体出力`、`See-Through補正`、個別RIFE補間は削除せず、
制作ホームの `既存プロジェクトの再作業` として残す。これらは新規制作の入口ではない。

ユーザーへ技術候補を並べて選ばせず、順番に作業できる主導線へ寄せる。
PachiPakuGen は生成APIを直接呼ばない。画像生成はアプリ外の Codex セッションに任せ、
アプリは Codex へ渡すジョブ作成、戻ってきた Codex生成素材の検査、See-Through分解、
RIFE出力に集中する。

- 分解: 内蔵See-Throughで素体候補・目・眉・前髪を構成し、人間が確認・補正
- 目: See-Through レイヤー抽出を主力、SAM3 を位置ゲート・失敗時補助に利用
- 口: Codex生成素材を See-Through で分解し、口レイヤーだけを抽出。SAM3/手動マスクは補助
- 補間: 既存 RIFE
- 生成: アプリ外の Codex ImageGen に依頼し、アプリ内APIキーや生成API呼び出しは使わない

## 2. Main Workflow

| Step | User-facing decision | Hidden or automated work |
|---|---|---|
| 1. 立ち絵 | 開眼・口が確認できる元画像1枚、任意の参照画像を選ぶ | 入力契約と不足確認 |
| 2. 素体作成 | 実行プロファイルと自動分類結果を確認し、必要箇所だけ補正する | 内蔵See-Through実行、素体候補作成、eyes-open抽出、前髪分離、SAM3ゲート |
| 3. Codex依頼 | 作る差分、口角、口サイズ、追加指示を確認し、Codex用ジョブを書き出す | `source.png`、`reference.png`、`codex_request.md`、`generated_parts/` を作成 |
| 4. 生成素材読込 | Codexが作った生成素材フォルダを読み込む | ファイル名、サイズ、必須差分、不足差分を検査 |
| 5. 生成素材分解 | 採用対象と失敗差分を確認する | 各生成素材をSee-Throughで分解し、目/口レイヤーだけ抽出 |
| 6. プレビュー調整 | 素体 + 目/口差分の合成を確認し、必要なら位置補正する | 採用/不採用、小さな移動、スケール、手動補助 |
| 7. RIFE出力 | まばたき・口パク・母音別フレームを生成する | RIFE補間、SpriTalk向けフォルダ/manifest/zip更新 |

## 3. Visibility Rules

- APIキー入力、API概算、GPT Image / Nano Banana の選択を通常フローへ表示しない。
- Codex生成待ちは正規ステップとして扱い、「Codexへ渡す」「生成素材を戻す」を明示する。
- 外部の素体・PSDアップロード欄を通常フローへ表示しない。
- See-Throughの生レイヤーは内部成果物として保存し、分解確認画面から修正できる。
- FACSと補助プロンプトは `Codex依頼の詳細` に格納し、既定では閉じる。
- 手動マスクや手動レイヤーマッピングはSee-Through分類失敗時または明示的上書き時だけ表示する。
- `eyes-open` は常にSee-Throughから抽出し、Codex生成対象にしない。
- `base.png` は自動構成後に必ず人間が確認・承認し、承認後は後続工程で不変とする。
- ユーザー向け用語は `ドナー` ではなく `Codex生成素材` または `表情差分素材` とする。
- フォルダ名は日本語パス事故を避けるため `generated_parts/` を標準とし、表示名を `Codex生成素材` にする。

## 4. Embedded See-Through Boundary

See-Through は PachiPakuGen が管理する Python ワーカーとして実行する。

- 初回だけモデルと実行環境をセットアップする。
- GPUメモリを検出し、通常版または省VRAM版を選ぶ。
- 入力画像、進捗、ログ、出力PSD・PNG群をPachiPakuGenが管理する。
- 出力PSDを既存のPSD解析処理へ直接渡し、自動レイヤー分類を行う。
- 自動構成が不十分な場合だけ、既存の `素体出力` と `See-Through補正` 相当の編集UIを
  同じワークフロー内に展開する。
- ワーカーが利用できない場合は、上級者向けに外部PSDを読み込む復旧経路を残す。

## 5. Layout

`DESIGN.md` の三領域原則に従う。

1. 固定ヘッダー: ワークフロー名、現在ステップ、生成素材の不足状態
2. スクロール可能な作業領域: 左に判断項目、右に制作プレビューと現在構成
3. 固定フッター: 前へ、進捗、次へ、ジョブ書き出し、生成素材読込、RIFE出力

制作ホームでは、推奨ワークフローを大きな主カードとして表示し、
個別ツールは小さく二次配置する。

## 6. STEP3 Implementation

- `src/App.tsx`
  - 新しい `expression` モード
  - 制作ホーム
  - 4ステップのUI
  - 立ち絵1枚だけを必須とする入力画面
  - 内蔵See-Throughの実行プロファイル・自動分類・補正方針
  - 対象差分、口角、口サイズ、Codex依頼文
  - Codex用ジョブ書き出し
  - Codex生成素材フォルダの検査と不足表示
- `src/App.css`
  - DESIGN.md準拠の制作ホーム、作業パネル、固定フッター
  - 既存個別ツールを維持したレスポンシブレイアウト

STEP4で内蔵See-Throughワーカーを接続した。

- ランタイム状態・GPU・推奨プロファイルをSTEP2へ表示
- 初回セットアップを明示ボタンから実行
- 解析進捗とキャンセルを表示
- 生成PSDを既存PSDパーサーへ直接渡して自動分類
- 分類別プレビューと全体合成を表示
- 分解結果の承認までSTEP3以降をロック
- 必要時に既存の高度なレイヤー補正画面へ遷移し、表情セット作成へ戻る

Codex生成素材の一括See-Through処理、目/口レイヤー抽出、元画像PSDへの再配置は
後続実装とする。SAM3自動マスクは標準の抽出経路ではなく、位置ゲートと失敗時補助として接続する。

## 7. Gate 3 Approval Items

1. 通常ユーザー向け入口を `表情セット作成` に一本化する。
2. 新規制作の必須入力を立ち絵1枚だけにする。
3. See-Throughを内蔵ワーカー化し、PSDをユーザーへ要求しない。
4. 既存機能は `既存プロジェクトの再作業` として維持する。
5. `立ち絵 → 素体作成 → Codex依頼 → 生成素材読込 → 生成素材分解 → プレビュー調整 → RIFE出力` の順次ステップを採用する。
6. 技術方式は推奨値を初期設定し、手動補正とCodex依頼の詳細は必要時だけ表示する。
7. アプリ内API生成ルートは通常導線から外し、Codex生成素材の受け渡しを本線にする。
