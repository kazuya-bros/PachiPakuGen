# Animation Lab — パラメータ軸パペット比較サンプル

SpriTalkの口パク・体・髪アニメーション改善のための技術比較アプリ。
**`index.html` をブラウザ（Chrome/Edge）で開くだけ**で動く（ビルド・サーバー不要）。

## コア発想: 「RIFE連番＝焼き込みパラメータ軸」

現行SpriTalkは連番フレームを時間順に等速再生している。本アプリでは
フレームインデックスを **0〜1の連続パラメータ** として扱い、
エンベロープ・バネ物理・ノイズ・モーラタイミングでスクラブする。
これはLive2Dのパラメータ（口開度・目開き・顔向き…）と同じ操作モデルで、
既存のPachiPakuGenワークフロー（GPT-Image2差分＋RIFE補間）を
「パラメータ軸工場」として利活用できることを実証する。

## 使い方

1. `index.html` を開く
2. **「🧪 モック素材で試す」** で即開始、または手持ちのPachiPakuGen出力フォルダを
   ドラッグ＆ドロップ / 「📁 素材フォルダ読込」
3. ▶再生。セルごとに口パク方式（A0〜A3）×体髪方式（B0〜B3）を切り替えて比較
4. 左のパラメータスライダーはリアルタイム反映

### 素材フォルダ構造（PachiPakuGen出力互換）

```
output/
  body.png            必須（口閉じ状態を含む）
  hair.png            任意
  hair_back.png       任意
  arm_l.png           任意（左腕。読み込むと腕揺れが有効になる）
  arm_r.png           任意（右腕）
  eye/                frame_001.png... （開き→閉じ）
  mouth_a/ 〜 mouth_o/ frame_001.png... （閉じ→全開）
  axis_<名前>/         拡張: 汎用パラメータ軸（例 axis_face_lr/ 左端→正面→右端）
```

連番は `frame_001.png` / `001.png` どちらでも可（数値部分でソート）。

## 比較する方式

### 口パク（同一モーラタイミングで駆動）

| 方式 | 内容 | 使う素材 |
|------|------|---------|
| A0 | 現行方式再現（等速ステップ送り・母音間で閉じて開き直す） | RIFE連番全フレーム |
| A1 | 調音結合（開度を維持したままレイヤー即差替え＋エンベロープ） | RIFE連番全フレーム |
| A2 | クロスフェード（2キーフレームのopacityブレンド） | **端点キーフレームのみ** |
| A3 | メッシュモーフ（頂点補間＋口内クロスフェードのハイブリッド、pixi/WebGL） | **端点キーフレームのみ** |

A4開度エンベロープ（attack/release）はA1〜A3の駆動信号。「矩形」に切り替えると現行相当の駆動になる。

### 体・髪

| 方式 | 内容 |
|------|------|
| B0 | 現行方式再現（sin波translate、本体と同じ定数） |
| B1 | スプリング遅延追従（頭の速度に髪がバネ遅延で追従） |
| B2 | 発話反応（発話開始squash&stretchバウンス＋開度連動の揺れ振幅） |
| B3 | メッシュ髪揺れ（角度チェーン物理、根元固定・毛先ほど柔らかい、pixi/WebGL） |

**腕揺れ（待機モーション拡張）**: arm_l/arm_r 読込時、体方式から独立して常時併用可能。
肩ピボットは不透明領域から自動推定。DOMセル=剛体回転、pixiセル=メッシュチェーン。
パラメータは「腕揺れ（待機拡張）」セクション。

**🎛 移植UI案**: A1＋B3＋腕揺れ採用前提の「キャラクター設定 › アニメーション」UI案を
動くオーバーレイとして実装（値は比較セルに即時反映）。保存データ構造案
（AnimationSettingsV2）も現在値から生成・コピーできる。
仕様: `docs/_local-archive/animation-lab-tech.md`（開発時のローカル参考資料、非トラッキング）

### 軸デモ

- **まばたき**: ヘッダの選択で「半目保持（ジト目）」「眠気」を試せる
  → 等速再生では不可能な「中間フレームの保持」が軸スクラブの価値
- **軸ラック**: `axis_*` フォルダ（モック時は顔向きLR/UD）を任意の駆動源
  （手動/等速/エンベロープ/ノイズドリフト/バネ+頷き）でスクラブ

## A3 対応点編集

「✏️ A3対応点編集」で開くエディタ:

- **ROI設定**: 口領域を矩形ドラッグ
- **頂点編集**: 母音（A/I/U/E/O）を選び、トレース表示された全開キーフレームに
  合わせて頂点をドラッグ
- **JSONエクスポート/インポート**: MorphData形式
  ```json
  { "version": 1, "roi": {"x":0,"y":0,"w":0,"h":0},
    "grid": {"cols":6,"rows":5},
    "targets": { "a": [[dx,dy], ...], "i": [...], ... } }
  ```
  → **将来PachiPakuGenの出力段に追加する「キーフレーム＋対応点」モードの仕様の叩き台**

## 観察チェックリスト（比較の見どころ）

- [ ] A0で母音が変わる瞬間の「パクパク感」（閉じ→開き直し）が再現されているか
- [ ] A1で同じ素材のまま母音間遷移が滑らかになるか（調音結合の効果）
- [ ] A2で口輪郭が二重に見えるか → 見える場合、キーフレームの口領域の重なり精度が素材要件
- [ ] A3で口周辺の歪みが許容範囲か / ROI外へのはみ出しがないか
- [ ] A3ハイブリッドの口内出現タイミング（innerStart/innerFull）の自然な設定値
- [ ] 軸スクラブを逆方向に動かした時のRIFEフレームの見え方（順方向前提で生成されているため）
- [ ] B1のk/cをどこまで振っても発散しないか（臨界ボタン=安定の基準点）
- [ ] エンベロープ「矩形」→「エンベロープ」切替での印象差（緩急の効果）

## 新軸用の指示書テンプレート要件（GPT-Image2差分の作らせ方）

比較で見えた素材要件。PachiPakuGenの指示書テンプレートに追加する際の指針:

1. **キーフレームは口周辺の肌ごと含める**（口だけ切り抜くとA3ワープ時に下の閉じ口が透ける。
   モック素材の「肌パッチ」が実証例）
2. **差分間で位置・色味を固定**（クロスフェードのにじみは位置ズレに比例する）
3. 顔向き軸は**1次元1軸**（左右と上下は別軸に分ける。同時合成はメッシュの領域）
4. 軸の端点2枚（＋必要なら中央1枚）があればRIFE補間で軸化できる

## pixi.js について

- CDN（jsdelivr）から自動読込。オフライン環境では
  https://cdn.jsdelivr.net/npm/pixi.js@8/dist/pixi.min.js を
  `vendor/pixi.min.js` として保存すればそちらが優先される
- pixi読込失敗時、A3/B3セルはDOMフォールバック（バッジに表示）

## VOICEVOX連携（任意）

VOICEVOX（localhost:50021）起動中なら、フッターのテキスト入力から
実音声＋実モーラタイミングで再生できる。未起動でも埋め込みデータで全機能動作。

| 本アプリ | 本体の移植元/準拠先 |

| getVowelAtTime / vowelToMouthLayer | `src/shared/utils/vowel-timing.ts` |

| B0 | `src/shared/animation/procedural-animator.ts` |
| 素材フォルダ規約 | `src/main/settings/layered-sprite-importer.ts` |
| VOICEVOXモーラ抽出 | `src/main/engines/mora-extractor.ts` |

方式ロジック（20/30番台）はコンポジター非依存の純関数構成なので、
検証で勝った方式はそのまま本体（DOMレンダラー）へ移植できる。
